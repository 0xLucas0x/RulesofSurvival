# Backtest 改进清单（叙事优先）

更新时间：2026-02-26

## 目标与评估口径
- 主目标：提升故事合理性、观赏性、玩家决策参与感。
- 次目标：维持系统稳定性（超时、错误率），胜率不作为一阶优化目标。

## 现状快照（来自最近回测）

### A. 100 局混合策略（`tmp/backtest-100x20-gpt53codex-local-mixed-20260226-001622`）
- 总计：100/100 完成，错误 0。
- 结局：`game_over=97`，`victory=3`。
- 失败原因分布：
  - `fall_unstable_seal=38`
  - `fall_sanity_depleted=26`
  - `fall_route_incomplete=24`
  - `fall_rule_chain_break=9`
- 叙事一致性：`reasonEndingMismatchCount=0`（结局标签与终局原因匹配稳定）。
- 文本重复度：`uniqueFinalSnippetCount=100`（终局片段重复低）。
- 公平性风险：`highProgressFailCount=13`（规则/道具/理智仍较高但失败，玩家可能感到“被系统硬收束”）。

### B. Agent+Memory 基线（`tmp/backtest-20x20-gpt53codex-agent-memory-20260226-085157`）
- 总计：20/20 完成，错误 0。
- 结局：`victory=5`，`game_over=15`。
- 失败几乎全部集中：`fall_route_incomplete=15`。
- 决策分布偏保守：`investigate` 占比过高，`risky` 极低。

### C. Agent+Memory 调参版（`tmp/backtest-20x20-gpt53codex-agent-memory-tuned-20260226-091340`）
- 总计：20/20 完成，错误 0。
- 更长流程后，失败类型变多：`unstable_seal`、`route_incomplete`、`rule_chain_break`。
- 但 guard 触发接近 0，说明当前“记忆防护阈值”对真实局面影响不足。

## 需要改进的点（按优先级）

## P0（先做）
- 终局公平性与可解释性
  - 问题：存在“高进度仍突然失败”的观感。
  - 改进：在终局前 2-3 回合加入“可逆预警”与“最后补救支线”，避免无提示硬收束。
  - 验收：`highProgressFailCount` 从 13 明显下降。

- `fall_route_incomplete` 的单一化
  - 问题：失败理由集中，玩家感受像“被同一机制反复惩罚”。
  - 改进：补充 2-3 条不同的路线闭环条件（如证据闭环、身份闭环、电路闭环），并给出分歧线索。
  - 验收：route 类失败占比下降，失败类型分布更均衡。

- 收束节奏过硬
  - 问题：中后段容易进入“强制推进+突然结算”。
  - 改进：软化最后 3 回合文案和机制，给“观察->修正->执行”的完整闭环。
  - 验收：玩家在终局前至少有一次明确“纠错决策”。

## P1（建议跟进）
- Agent 选择器“记忆”有效性
  - 问题：已接入 memory/guard，但触发率低，实战影响弱。
  - 改进：
    - 放宽 guard 触发条件（减少仅靠 `risky` 计数的依赖）；
    - 增加“目标缺口驱动”的动作偏好（缺规则补 investigate，缺道具补 item，缺稳定度补低风险 move）；
    - 将“连续同类动作惩罚”从硬规则改为温和权重惩罚。
  - 验收：choice 分布不再单极化，且终局体验更可控。

- 叙事状态记忆（story memory）
  - 问题：局部信息有时未被后续充分回收。
  - 改进：引入结构化记忆摘要（已确认事实、未解矛盾、高风险触发器），每回合注入生成上下文。
  - 验收：终局解释回收率提升，伏笔回收更自然。

## P2（长期）
- 叙事质量自动评分管线
  - 增加 5 个自动指标：
    - 因果连贯度
    - 伏笔回收率
    - 玩家可解释失败率
    - 结尾突兀度
    - 决策分支感知度
  - 使用批量评审模型（可用高速 provider）做离线打分，和回测 summary 一起输出。

## 参数优先方案（不改代码先试）
- 目标：先验证“收束软化”是否改善观感。
- 建议组合：
  - `TEST_MAX_TURNS=17~18`
  - `TEST_AGENT_TEMPERATURE=0.25~0.35`
  - `TEST_AGENT_HISTORY_TURNS=8`
  - `TEST_AGENT_MEMORY_TURNS=6`
  - 将终局前提示窗口提前到 `T-3`（如果已有 env 控制，优先走参数）
- 说明：这组参数不是为了提胜率，而是为了增加“可读、可理解、可反应”的终局过程。

## 实施顺序
1. 先做 P0（三项）并回测 50 局（并发按当前 provider 能力配置）。
2. 再做 P1（记忆触发与结构化摘要）并回测 50 局。
3. 最后接入 P2 自动评分，形成“数值 + 文本”双维报告。

## 回归验收建议
- 基础稳定性：错误率、超时率不高于当前基线。
- 叙事体验：
  - `highProgressFailCount` 下降；
  - 终局样本抽检中“可解释失败”占比提高；
  - 玩家视角的“最后一跳突兀感”下降。
